# Audit a Claude Code setup for the move from Sonnet 5 to Sonnet 5.5

**This skill covers one model transition, Claude Sonnet 5 → Claude Sonnet 5.5, and nothing older.** Every pattern it flags comes from Anthropic's official guides for that transition, the Claude Code documentation, or the Claude Sonnet 5.5 System Card, cited in [Sources](#sources). An instruction that was already outdated on Sonnet 5 is reported as older residue and left alone.

**It has three jobs, and every stage below serves one of them.** Be transparent before spending anything: show the plan, the cost and the options, and let the user choose. Explain what it found in the chat, plainly enough that the user understands each change without opening a file. Ask what to do, with a recommendation, and change nothing the user did not approve.

**While it runs, the chat carries only progress and the decisions taken with the user, who should read as little as possible to decide.** Reference material — coverage, what was not audited, older residue, counts by confidence — goes to the report file and the close.

## Stage 2 — Audit in batches

<line_format>

One line per finding, its six fields separated by ` | `:

`<file>:<line> | <pattern id> | <status> | "<quoted text>" | <confidence> | <note>`

- `<file>` is the path relative to the audit root, and `<line>` the line that carries the row's signal — the pin, the call's argument, the quoted instruction — where the quoted text starts, never a function head, a block opener or a nearby setting.
- `<pattern id>` is the id of one row of the pattern table, such as `P09`.
- `<status>` is `change`, `already decided`, `older residue` or `unclear` in a batch's lines; the verifier's final list may also use `re-test`, `optional` and `discarded`.
- `<quoted text>` is the text exactly as it appears in the file, trimmed to the words that match the row.
- `<confidence>` is `high`, `medium` or `low`.
- `<note>` is the proposed change in a few words for `change`, `re-test` and `optional`, where the project records the decision for `already decided`, the reason for `unclear` and `discarded`, and `-` for `older residue`.

Record one line per pattern per `file:line`: a second pattern firing on the same construct gets a line of its own, and a note never stands in for another `file:line`, except a P06 convention line or an [N31] decision line, which names every file it covers.

A batch with no finding is recorded as this line alone:

`clean`
